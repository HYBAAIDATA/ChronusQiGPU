## Core Principle
**One Intelligence Console. Infinite Client Variants.**
Clients don't see "products." They see **capabilities** that feel like different lenses on the same computational substrate. The frontend must behave like a **shape-shifting intelligence surface** — same engine, different skin, permissions, connectors, and workflows per sector.
**Reference calibre:** Snowflake (data cloud) × NVIDIA NGC (compute fabric) × OpenAI Playground (intelligence surface) × Palantir Foundry (governance + ops) × Apple Design Award (polish) — all fused into one.

## 7. Multi-User, Multi-Product, Multi-Billing Architecture
### Organizations
- Multiple users per organization
- Roles: Admin, Analyst, Engineer, Auditor
- SSO: Azure AD, Okta, Google Workspace
### Billing
- Per-product billing
- Per-seat billing
- Per-usage billing (GPU hours, QC cycles, compression volume)
- Enterprise invoicing
- Usage forecasting
### Governance
- Audit logs
- Evidence retention policies
- Compliance modes (Basel III, GDPR, NIST, ISO, Sovereign AI)
- Data residency enforcement (EU, UAE, UK, KSA)
### Workflows & DSAR
- **Workflow engine:** Sector-specific workflow templates (risk assessment, compliance review, data processing)
- **Purge workflows:** Data deletion workflows with audit chain evidence — when data is archived or purged, the audit chain records the action with hash-linked evidence
- **DSAR (Data Subject Access Request):** GDPR Article 15-21 compliance — when a client's archived data needs to be surfaced or purged:
	- DSAR intake form → identity verification → data discovery across folded state → export or purge → audit chain evidence → compliance report
	- PULVINI folded data must be unfolded for DSAR discovery — the fold is invertible, so no data is lost
	- Purge workflow: unfold → identify subject data → purge → re-fold → audit chain entry → compliance certificate

## 11. Design Principles
1. **One organism, many lenses:** Same UX skeleton, different "modes" per product.
2. **Evidence-first:** Every action has an "Evidence" tab — JSON artifacts, audit chain entries, compliance reports.
3. **Honest state:** Clearly show "mock", "research", "production" labels — no pretending.
4. **Composable:** Everything feels like operators, not one-off tools.
5. **Sector-adaptive:** Same engine, different skin, permissions, connectors, and workflows per sector.
