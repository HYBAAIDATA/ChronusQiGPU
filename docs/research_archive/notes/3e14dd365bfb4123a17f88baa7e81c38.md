## What This Is
Chronos GPU renders scenes by exactly diagonalising a scene Hamiltonian built on a real M32 manifold, then ray-tracing a pinhole camera against the scene and shading hit points from the computed per-face quantum state. Quantum computation is treated as substrate- and hardware-agnostic mathematics: there is no physical apparatus, no cryogenics, and no hardware dependency anywhere in the package.
The engine is a single source of truth in `src/chronos/`; the top-level scripts are thin compatibility shims that re-export it.
## Verified Implementation
- **Real M32 manifold geometry** — icosahedron + dual-dodecahedron construction via the golden ratio (`manifold.py`), replacing the earlier Fibonacci-sphere placeholder
- **Real QSDL v1.0 language front end** — tokenizer plus recursive-descent parser implementing the full published BNF grammar (`qsdl_parser.py`), and a compiler that turns genuine `scene NAME { ... }` source into a `QScene` (`qsdl_compiler.py`)
- **Exact ground-state solve** of the scene Hamiltonian by dense eigendecomposition, with the mixer term actually contributing to the total Hamiltonian
- **Real pinhole-camera ray tracing** shaded by per-face probability amplitude — not a placeholder flat fill
- **Honestly computed raster-compression metadata** (state bytes vs. dense frame bytes); no unconditional "11.5×" claim
- **Self-consistent BCS superconducting-gap solver** — numeric solution of the true gap integral, not just the closed-form interpolation
- **Real 1000-qubit tensor-train computation** — a genuine 1000-qubit GHZ state at `bond_dim=64`, \~8K real parameters instead of a 2\^1000-amplitude dense vector, with exact Bell-state and entanglement-entropy self-tests
- **Test harness and pytest suite** wrapping every module's self-test into one entry point, plus a measured benchmark suite

### φ-power scaling (`phi_scaling.py`)
Runs the real pipeline with face counts set by `round(φ^n)`, cross-checked against an exact-integer Lucas-number identity. Eigendecomposition time grows from **0.019 s at 123 faces (φ¹⁰)** to **20.2 s at 5,778 faces (φ¹⁸)**; φ²⁰ (15,127 faces) is *projected* at \~123 s from the measured trend rather than executed on every call. This is honest evidence of classical O(n³)-ish dense-eigensolver scaling — explicitly **not** a quantum-speedup claim.

## Audit History
Thirteen defects were found and fixed against the original package, each confirmed by actually running the pipeline rather than by inspection:
- A `qsdl_source` typo that made the pipeline unimportable
- Unseeded global RNG producing non-deterministic energy (−1.06 / −1.17 / −1.14 across three runs)
- `EvolutionEngine.evolve` returning an unrelated random vector that never touched the Hamiltonian
- A hardcoded `energy = 0.123456` matching an unreproducible smoke-test result
- Reconstruction broadcasting one scalar across the whole 8K frame
- A hardcoded `fold_ratio: 11.5` contradicted by this workspace's own real tensor-train audit (0.44×)
- Two divergent duplicate implementations, since consolidated into `src/chronos/`
- A test harness that always printed "passed" regardless of behaviour
- A silently discarded mixer term, an over-strict 35° adjacency threshold, and negative-energy-as-brightness clipping — the three compounding root causes of a persistent flat render
Subsequent revisions closed the remaining gaps: real M32 geometry (which moved the baseline energy from −6.064956 to −7.337994), a real QSDL parser, the academic enhancement suite, the 10 theory domains, and the φ-power scaling benchmark. Two genuine Riccati-equation convention bugs were found and fixed while verifying `theory/control.py`.
## Claim Boundaries
- This package does **not** implement the physical-cryogenic "Enhanced Chronos Pseudocode" (1,000,000 resonators at 15 mK, weak measurement hardware, cryogenic control, QX API). That is a structurally different architecture and none of this code is reusable for it.
- All physical-lab-hardware specifications (Oxford materials/nanofab, ETH cryocoolers and vibration isolation, MIT photonics/CMOS, Tokyo Tech atomic clocks) are plain labelled specification dictionaries — nothing is simulated or claimed as run.
- No benchmark score is fabricated, and no trained model, LHC data, or compute is claimed that does not exist in the package. Toy-scale items (numpy PINN, adversarial pair, tabular Q-learning) are labelled as toy scale.
- Cambridge/Caltech ML components are honestly scoped: the surface-code decoder is a real brute-force minimum-weight decoder, not the claimed 6-million-sample trained neural network.
- No quantum speedup or exponential advantage is claimed anywhere. The φ-power benchmark measures classical dense-eigensolver scaling.
- References to Euclid, the golden ratio, and related history are **structural analogies only** — not claims that ancient sources contain quantum theory, and not a proof of any philosophy of physics. Passing tests verifies algorithms, not metaphysics.

### Elevation discoveries incorporated
1. **Precision is a first-class boundary.** The resident iGPU engine now exposes accumulator dtype and byte width so host buffers match the compiled kernel accumulator. An FP64 extension flag alone is not evidence of an FP64 path; structural and certifying 11-D state remains Float64 on the host/reference route until a distinct Chronus FP64 implementation is numerically certified. [\[5\]](https://github.com/QuantumPhiEnterprise/PYTHIPhiMiner/pull/7)
2. **Hardware selection is now semantic.** Alias names are preferences unless `HYBA_REQUIRE_HYBA` is enabled; Intel iGPU preference requires unified host memory, preventing discrete Arc-class devices from being misclassified as shared-memory iGPUs. Kernel launch planning is bounded by compiled-kernel work-group and local-memory limits, not only device-wide limits. [\[6\]](https://github.com/QuantumPhiEnterprise/PYTHIPhiMiner/pull/98)
3. **Unsupported execution fails closed.** Unsupported punch opcodes fall back to the CPU path rather than crashing or silently fabricating a result; geodesic hop budgets reset per query; invalid anchors are rejected; the dense quantum memory model raises an exact-resource error rather than approximating beyond its declared bound. [\[5\]](https://github.com/QuantumPhiEnterprise/PYTHIPhiMiner/pull/7)
4. **Tensor workloads are real and were used to find a latent defect.** The tensor-train remainder reshape bug failed for higher-dimensional tensors; the corrected path reconstructs a `(4,4,4)` rank-4 case at approximately `1e-17` error. The 11-layer measurement suite also runs real MPS, TT-SVD, and MPO workloads. [\[3\]](https://github.com/QuantumPhiEnterprise/PYTHIPhiMiner/pull/60)
5. **Advisory tensor output cannot alter mining correctness.** The measured tensor/iGPU/GPU/ASIC boundary permits tensor advice to reorder certified nonce windows only. It cannot mutate coverage, targets, ownership, spans, or the host SHA-256d acceptance boundary. No implied fold, tensor, genetic, or hashrate multiplier is part of the production equation. [\[7\]](https://github.com/QuantumPhiEnterprise/PYTHIPhiMiner/pull/29)
6. **Distribution is part of correctness.** The MLA1517 iGPU contract JSON is shipped as package data so installed wheels do not lose the hardware contract. Remaining import/package decisions must stay bounded; do not package an eager legacy tree merely to hide a missing dependency. [\[8\]](https://github.com/QuantumPhiEnterprise/PYTHIPhiMiner/pull/36)
7. **Chronos GPU discoveries remain correctly scoped.** The M32, QSDL, exact diagonalisation, real ray tracing, 1000-qubit MPS, theory domains, and φ-power benchmark are verified mathematical software. They do not implement cryogenic hardware, weak measurement backaction, QX, a physical QPU, or quantum speedup. See <mention-page url="https://app.notion.com/p/6c0bbde40e8b41eeba9cedb15d5bcb9b"/>.

### Physical evidence command
Run only on the target host with the requested hardware:
```bash
python3 -m bench.chronus_igpu_evidence \
  --size 512 \
  --iterations 20 \
  --stress-seconds 300 \
  --sha256d-count 1048576
```
The artifact must include physical device identity, capabilities, launch evidence, float32 reference comparison, sustained-load correctness and degradation, optional SHA256d throughput, sensed power/thermal data where available, topology, runtime/kernel/input/output binding, remote-agent status, a content hash, and validator output. Pool acknowledgement remains `Unavailable` unless independently observed.
