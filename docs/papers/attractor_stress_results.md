## The structural fact being exploited

For every k in {8, 16, 32, 64}, `M_k = I + 2A` with **A ≡ Q = [[1,1],[1,0]] (mod 2)**: the Hensel-lifted
M15 is the identity plus twice the Fibonacci matrix. It follows that `M_k^(2^t) ≡ I (mod 2^(t+1))`
(tested for every t < k), so `x ↦ M_k^x v` is **2-adically continuous with shift 1**: F(x) mod 2^(t+1)
depends only on x mod 2^t. `collapse_generator` can then fix generator j from a residue
test at precision j+2, one bit at a time. In other words, Hensel lifting runs on the folded register.

The stress test measures exactly that property (column "2-adic continuity": over all pairs
(i, i+2^t), t = 1..N−1, it counts how often F(i) ≡ F(i+2^t) mod 2^(t+s)), and then what each search method pays.

## Cost model and columns

One **oracle evaluation** is one evaluation of the problem observable F(state): a matrix power, a trace,
a polynomial, a subset sum, or a SHA-256d. A full query asks `F = target`; a graded query asks
`F ≡ target (mod 2^p)`. Both cost one evaluation and share one counter.

* **(i) linear scan**: full queries in natural order, counted to the first hit.
* **(ii) triad as built**: `run_triad_exact_grover_search` on the staged register. It evaluates the oracle on all W
  states, which is how M is known, then runs exact Grover to the peak and collapses the winner through THESEUS.
* **(iii) structure-exploiting triad variant** (`triad_structured`): graded queries on OVID-materialised states
  drive `commit_collapse_step` for the low N−4 generators. Where both lifts survive, the variant forks into child
  artifacts. It then runs the exact triad Grover over each branch's residual 2^4 = 16 states.
* **(iv-a) graded Hensel tree**: the same lift with the same access model, with no custody and no Grover.
* **(iv-b) best known classical**: white-box algorithms. Back-substitution (triangular elimination mod 2^k) for 2a.
  Newton–Hensel lifting of the simple 2-adic roots for 2b. Repeated squaring in the 2-group ⟨M_k⟩ for 1c.
  Meet-in-the-middle for 2d. Pohlig–Hellman, equivalent here to the 2-adic bit lift, for 1a. The 2-adic square-root
  lift for 2c. For 1b the bit lift is an **upper bound**, because a poly(k) route exists that I did not implement:
  solve Y² − τY + (−1)^x I = 0 in Z/2^k[M], then Pohlig–Hellman.
* **(q) ideal Grover**: the exact peak iteration count for (W, M) from `exact_grover_two_amplitude_trajectory`.
  **This is a query count on a quantum machine. It was not run here.** Black-box Grover cannot see structure,
  so (q) is identical for structured and unstructured instances with the same (W, M).

## Honest boundary statement

1. **Where the oracle is 2-adically continuous, collapse_generator gives a real, exact, exponential pruning.**
   This covers all of Test 1 and Tests 2a–2c, with continuity agreeing on every pair and receipts verified
   through THESEUS. At k = 32 the structure-exploiting triad needs 32 / 40 evaluations for the orbit hidden shift
   and 32 / 40 for order finding, against 4096 / 65536 for the triad as built and 3790 / 57038 and 1024 / 16384
   for the linear scan to first hit. The architecture really does contain a Hensel lifter: the M_k fold makes the
   oracle continuous, and `collapse_generator` is the lifting step.
2. **That pruning is classical, and a classical algorithm gets all of it.** The plain Hensel tree (iv-a) always
   uses fewer evaluations than the triad variant (iii); the difference is the residual stage. The best
   white-box classical methods (iv-b) use fewer still: 1 evaluation for 2a and 2b, and 11 / 15 for order finding.
   **No row shows an advantage from the quantum part of the architecture.** The Grover stage in (iii) evaluates
   all 16 residual states before it amplifies, as it must to know M. When several marked states share one branch,
   for example the two x of 1a at k = 16, W = 65536, which differ only in bit 15 because the orbit length is 2^15, the
   branch's Grover returns one of them. That is why "found" can be below M.
3. **Against the ideal Grover reference (q), which is a quantum-machine query count and was not run:** classical
   structured methods beat 50 / 201 queries on 1a, 1c, 2a, 2b, and on 2c at W = 65536. At these sizes (q) has the
   lower count in three places:
   * 1b, trace fibre: 248 vs 50 and 376 vs 201. The (iv-b) figure is an upper bound from the bit lift, whose
     width grows (ensemble max 600 at W = 4096 and 2424 at W = 65536), and a poly(k) classical route exists.
   * 2c at W = 4096: 78 vs 50. The square-root tree has width 4 and O(N) cost, and it overtakes by W = 65536.
   * 2d, dense subset sum: meet-in-the-middle 128 vs 50 and 512 vs 201. Both scale as 2^(N/2), and the published
     quantum subset-sum algorithms (Bernstein–Jeffery–Lange–Meurer 2013; Helm–May 2018) improve the exponent over
     the best classical (Becker–Coron–Joux 2011).

   2d is the one regime where the literature knows quantum hardware to beat the best classical method. It needs a quantum machine;
   on this box the triad still pays W evaluations there.
4. **Without continuity (2d, Test 3), collapse is inadmissible.** The graded lift loses the target in the
   instances above, in 0 of the 481 and 499 subset-sum instances, and in 1 of 500 headers at each SHA-256d window
   size, which is chance level. The only correct triad path is then the as-built one: W evaluations, about 2× the
   linear scan's expected first hit. The SHA-256d continuity census agrees on 4084 / 40962 pairs at W = 4096 and
   65602 / 917506 at W = 65536. Chance predicts Σ_t (W/2^t − 1) = 4083 and 65519. Every algebraic family agrees
   on 100%. That census is the empirical boundary: **structural
   compression exists exactly where F(i) mod 2^(t+s) depends only on i mod 2^t, and SHA-256d mining is on the
   other side of it.**
5. **The scope of "Grover in O(1)".** The exact two-amplitude evolution takes O(1) state per step in Q². It is
   exact bookkeeping of a quantum algorithm's amplitudes. It needs M, and classically M is obtained by evaluating
   the oracle on all W states. So the claim the data supports is: exact rational O(1)-per-step amplitude
   evolution, with O(W) classical oracle cost on unstructured oracles, and the classical Hensel cost
   O(N · width) wherever the M_k fold makes the oracle 2-adically continuous.

## Correctness fix found while wiring Test 2/3 (file:line)

`src/chronus/quantum/triad_grover.py:172` (on `feat/grok-triad-grover` @ `3072a50d`): `win_idx = offsets[win]` carries only
the active-position bits. When a handle arrives with generators already collapsed, the resolved bits are
dropped and the read-out check at `:178` raises `ArithmeticError("collapsed read-out disagrees with materialised winner")`.
`winner_index` is also under-reported. Fixed in this branch as `win_idx = offsets[win] | handle.register.resolved_bits`.
The regression test is `test_residual_search_after_prior_collapse_reports_full_index`, and it fails on `3072a50d`.
`ProductionTriad.exact_grover_search` always stages a fresh handle, so the published W = 4096 / 65536 benchmark is unaffected.
