# Category & Delivery Doctrine — CIaaS

<aside>
🎯

**BLUF.** HYBA does not fit existing software categories. The category is **Computational Intelligence as a Service (CIaaS)**. HYBA Data is not SaaS. Delivery, billing, and operations follow a self-healing, multi-cloud availability model — not maintenance-led software.

</aside>

---

## Category

| Statement | Doctrine |
| --- | --- |
| **Category name** | **Computational Intelligence as a Service (CIaaS)** |
| **Why it exists** | HYBA does not fit any current category — so HYBA defined its own |
| **HYBA Data** | Has no equal; sets a new standard within CIaaS |
| **Not SaaS** | HYBA is **not** SaaS and does not operate as SaaS |

**External language:** lead with CIaaS. Do not default to “SaaS,” “AI app,” or “analytics tool.”

---

## What we are not (SaaS rejection)

| SaaS default | HYBA Data doctrine |
| --- | --- |
| Seat / subscription maintenance model | **Not** how we bill or deliver |
| Charge for maintenance | **We do not charge maintenance** |
| Human ops to keep the product running | **There is nothing to maintain** in the traditional sense |
| Patch cycles as the product story | Software **heals and optimises itself** |
| Single-cloud / tenant-app posture | **Service availability across all major cloud providers** |

---

## Delivery & operations posture

1. **Self-healing / self-optimising software** — core delivery claim; not a marketing flourish  
2. **No maintenance fee** — because there is nothing to maintain under this model  
3. **Uptime:** **99.999%** — stated as operational standard, **not marketing language**  
4. **Deployment strategy:** service availability across **all major cloud providers**  

### Evidence discipline (mandatory before external use)

Per HYBA gates (Oxford–CERN science bar; extraordinary claims → extraordinary proof; cite everything):

| Claim | External rule |
| --- | --- |
| CIaaS category | Positioning — may state; define clearly |
| Not SaaS / no maintenance | Commercial doctrine — state with billing model when ready |
| Self-heals / self-optimises | Requires technical evidence pack before customer/press |
| **99.999% uptime** | Requires measurement method, window, scope, and proof — or stays internal |
| Multi-cloud availability | Requires named providers + deployment architecture evidence |

**Doctrine:** It is not hyperbole if it is true and evidenced. Confidence is required. Proof is required before it leaves the ecosystem.
