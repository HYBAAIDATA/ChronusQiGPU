# Turing Workflow 04 — OVID Transformation & Fold Contract

## Purpose

Govern every use of OVID to transform, fold, materialise, encode, regenerate or convert Turing state.

## Required contract

Source Turing representation; OVID transform identifier/version; mathematical mapping; retained residual/conjugate information where required; invertibility/reconstruction condition; target Turing representation; invariants; error bound; provenance.

## Tests

Round trip; independent reconstruction; measurement/result equivalence; boundary sizes; adversarial state classes; precision stress; repeated transform cycles; corrupted transform metadata; unsupported-state fail closed.

## Authority

OVID owns the transformation implementation. Turing decides whether the transformed state remains valid for Turing semantics.

## Promotion rule

No generic compression/fold advantage may be inferred from one structured family. Measure metadata, reconstruction, memory movement and quality/exactness for the exact workload.
