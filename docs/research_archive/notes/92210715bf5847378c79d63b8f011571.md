## 1. Add `scripts/run_staging_qualification.ps1`
```powershell
# Staging only. Do not use against production without an approved change window.
$ErrorActionPreference = "Stop"

if (-not $env:BASE_URL -or -not $env:BASE_URL.StartsWith("https://")) {
    throw "BASE_URL must be a staging HTTPS URL"
}
if (-not $env:TEST_USER -or -not $env:TEST_PASS) {
    throw "TEST_USER and TEST_PASS must be supplied through secure environment variables"
}
if (-not (Get-Command k6 -ErrorAction SilentlyContinue)) {
    throw "k6 is required. Install it from the approved engineering toolchain."
}

$timestamp = Get-Date -Format "yyyyMMdd-HHmmss"
$artifactDir = "artifacts/staging-qualification/$timestamp"
New-Item -ItemType Directory -Force -Path $artifactDir | Out-Null

Write-Host "Running controlled k6 staging qualification against $env:BASE_URL"
k6 run `
  --summary-export "$artifactDir/k6-summary.json" `
  --out "json=$artifactDir/k6-events.json" `
  benchmarks/load_test_k6.js

python scripts/evaluate_k6_summary.py "$artifactDir/k6-summary.json" |
  Tee-Object -FilePath "$artifactDir/evaluation.json"

@{
  timestamp_utc = (Get-Date).ToUniversalTime().ToString("o")
  base_url = $env:BASE_URL
  test = "benchmarks/load_test_k6.js"
  result_artifact = "$artifactDir/k6-summary.json"
} | ConvertTo-Json | Set-Content "$artifactDir/manifest.json"

Write-Host "PASS: staging qualification evidence written to $artifactDir"
```
## 2. Add `scripts/evaluate_k6_summary.py`
```python
#!/usr/bin/env python3
"""Fail-closed evaluator for k6 summary-export evidence."""
from __future__ import annotations

import json
import sys
from pathlib import Path

LIMITS = {
    "p95_ms": 200.0,
    "p99_ms": 500.0,
    "error_rate": 0.01,
}


def value(metrics: dict, metric: str, field: str) -> float:
    try:
        return float(metrics[metric]["values"][field])
    except (KeyError, TypeError, ValueError) as exc:
        raise SystemExit(f"FAIL: missing k6 metric {metric}.{field}") from exc


def main(path: str) -> None:
    report = json.loads(Path(path).read_text(encoding="utf-8"))
    metrics = report.get("metrics", {})
    p95 = value(metrics, "http_req_duration", "p(95)")
    p99 = value(metrics, "http_req_duration", "p(99)")
    errors = value(metrics, "http_req_failed", "rate")
    checks = {
        "p95_ms": {"value": p95, "limit": LIMITS["p95_ms"], "passed": p95 < LIMITS["p95_ms"]},
        "p99_ms": {"value": p99, "limit": LIMITS["p99_ms"], "passed": p99 < LIMITS["p99_ms"]},
        "error_rate": {"value": errors, "limit": LIMITS["error_rate"], "passed": errors < LIMITS["error_rate"]},
    }
    result = {"result": "PASS" if all(c["passed"] for c in checks.values()) else "FAIL", "checks": checks}
    print(json.dumps(result, indent=2))
    if result["result"] != "PASS":
        raise SystemExit(1)


if __name__ == "__main__":
    if len(sys.argv) != 2:
        raise SystemExit("usage: evaluate_k6_summary.py <k6-summary.json>")
    main(sys.argv[1])
```
## 3. Add `monitoring/alerts/staging-readiness-rules.yml`
```yaml
groups:
  - name: midas-staging-readiness
    rules:
      - alert: MIDASApiUnavailable
        expr: up{job="midas-api"} == 0
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: MIDAS API target is unavailable
          runbook: docs/PRODUCTION_RUNBOOK.md

      - alert: MIDASHighServerErrorRate
        expr: |
          sum(rate(http_requests_total{job="midas-api",status=~"5.."}[5m]))
          /
          clamp_min(sum(rate(http_requests_total{job="midas-api"}[5m])), 1)
          > 0.01
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: MIDAS server error rate exceeded 1 percent for five minutes
          runbook: docs/PRODUCTION_RUNBOOK.md

      - alert: MIDASHighP95Latency
        expr: |
          histogram_quantile(0.95,
            sum(rate(http_request_duration_seconds_bucket{job="midas-api"}[5m])) by (le)
          ) > 0.2
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: MIDAS p95 API latency exceeded 200 ms for ten minutes
          runbook: docs/PRODUCTION_RUNBOOK.md
```
**One-time integration control:** validate the metric names and `job="midas-api"` label against the running Prometheus target before enabling alerts. Do not silently rename metrics to make the rules appear green.
## 4. Add `docs/STAGING_QUALIFICATION_PROTOCOL.md`
```markdown
# MIDAS Staging Qualification Protocol

## Preconditions
- Release candidate passed required CI and security regression tests.
- Test identities are dedicated, least-privilege staging identities.
- No live pool, wallet, credential, or share-submission configuration is enabled.
- Observability target, alert routing, and rollback owner are declared.

## Workload sequence
1. **Baseline:** 10 minutes at expected staging demand.
2. **Two-times demand:** run the k6 ramp at 2× forecast demand.
3. **Spike:** execute the existing 10× sudden-load profile.
4. **Soak:** sustain representative demand for 6 hours; extend to 24 hours before production approval.

## Pass thresholds
- p95 latency < 200 ms
- p99 latency < 500 ms
- HTTP error rate < 1%
- No sustained memory growth or process restarts
- No unapproved alert or SLO breach
- Authentication and authorization controls remain effective throughout the test

## Controlled resilience drills
Run one drill at a time in staging, with an observer and rollback owner:
- terminate one API process/pod;
- restart the cache dependency and validate safe recovery;
- introduce bounded dependency latency;
- validate circuit-breaker transition and recovery;
- roll back a deployment while representative load is active.

Do not run destructive network, database, pool, wallet, or credential exercises without an approved change window and a tested recovery procedure.

## Evidence to preserve
- release commit SHA/image digest;
- k6 summary and raw events;
- evaluator result and system-resource charts;
- alert timeline and trace/correlation samples;
- resilience exercise log and recovery evidence;
- operator, observer, duration, environment, and outcome.
```

2. Install/use the existing k6 benchmark toolchain; do not create a second incompatible load harness.
3. Validate alert metric names against Prometheus.
4. Run baseline, 2×, spike, and soak tests in staging.

## Exit condition
This package closes **evidence gaps only when its tests run and pass**. A committed script, alert file, or checklist is not performance, resilience, or production proof.
