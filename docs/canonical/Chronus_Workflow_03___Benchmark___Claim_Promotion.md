# Chronus Workflow 03 — Benchmark & Claim Promotion

<aside>

Material claim promotion or demotion requires explicit owner approval.

</aside>

## Controls

Freeze code/workload/input/environment; match useful work; match semantics/correctness; hold precision and quality constant unless explicitly varied; include setup/preprocessing/index/transfer/reconstruction/metadata when material; report cold/warm behavior; prevent cache asymmetry, early termination, favorable selection, async timing errors and benchmark-vs-production drift; preserve losing variants.

## Claim packet

Exact wording; prior state; proposed state; source code SHA; benchmark command; raw artifacts; environment/device; repetitions/statistics; baseline; correctness/quality delta; red-team verdict; limitations; falsification condition; owner approval.

## States

THEOREM-PROVEN · MATHEMATICALLY SUPPORTED · SOFTWARE-VERIFIED · VQC-VERIFIED · HARDWARE-MEASURED · PRODUCTION-EVIDENCED · CONDITIONALLY TRUE · NOT YET EVIDENCED · INCONCLUSIVE · REFUTED plus MEASURED/GATED/UNAVAILABLE/MISSING operational states.

## No promotion by narrative

README text, test presence, device presence, dispatch, or a single fast run is never sufficient by itself.
