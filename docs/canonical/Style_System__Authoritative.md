# Style System (Authoritative)

<aside>
⚖️

**DNA / posture.** HYBA is the McKinsey of the world. That is why the McKinsey executive style guide is adopted as authoritative institutional doctrine — not inspiration. Visual language: Oxford + McKinsey blues, Veuve Clicquot gold & orange, luxurious grey, sand. Primary type: **Victor Serif** (full weight range). Pairing sans TBD.

</aside>

---

## Posture

- **Institutional authority** equal to the world’s leading strategy firms
- **Universal mandate:** every presentation, deck, thought piece, announcement, and document must **mimic McKinsey** — structure, tone, exhibit logic, visual restraint, and board-grade hygiene. No casual formats. No startup pitch aesthetics.
- Answer-first / BLUF writing
- Pyramid structure and clean exhibit logic
- Evidence-backed claims only
- Board-grade document hygiene
- Quiet confidence — never decorative noise
- Blue carries the institution; gold is the prize; orange is the spark

### McKinsey form (required on every artifact)

1. **BLUF / answer first** — recommendation or insight in the first line
2. **Pyramid** — governing thought → supporting arguments → evidence
3. **One idea per slide / section** — no cluttered multi-thesis pages
4. **Exhibit discipline** — charts and tables titled with the insight, not the data category
5. **Action titles** — headlines state the conclusion
6. **Sparse colour** — navy structure; gold only for prize numbers; orange rare
7. **Victor Serif** for identity and executive type; pairing sans only when decided
8. **Evidence trail** — claims separable into implemented / validated / planned / aspirational
9. **Document hierarchy** — board paper → briefing → customer brief → PR → one-pager → technical annex → evidence pack

### McKinsey form (required on every product)

Every product brought to market must **look, feel, and perform** like a McKinsey deliverable:

1. **Look** — institutional visual system (Oxford/McKinsey blues, gold sparingly, sand/grey calm); no startup chrome
2. **Feel** — quiet authority in interaction: clear hierarchy, deliberate motion, zero clutter, board-readable density
3. **Perform** — production reliability, measurable outcomes, evidence-backed claims in-product, operational polish
4. **IA** — answer-first surfaces; insight titles on charts; executive summary paths before deep detail
5. **States** — empty, loading, error, and permission states designed to the same standard as happy path
6. **Onboarding** — structured like a briefing, not a consumer app tour
7. **Ship bar** — if it would embarrass a McKinsey client room, it does not ship

## Scientific & technical bar (ubiquitous)

**Publish standard:** If **Oxford, Cambridge, MIT, Caltech, or CERN** would not publish it, **neither will HYBA**.

This bar is **ubiquitous and pervasive** — not reserved for papers alone. It applies to:

- technical annexes and whitepapers
- validation reports and claim boundaries
- product science surfaces and in-product metrics
- methods, proofs, experiments, and reproducibility packs
- investor/technical diligence materials that assert science or performance

### Required discipline

1. **Falsifiability** — claims stated so they can be tested or bounded
2. **Evidence separation** — implemented / validated / planned / aspirational never mixed as fact
3. **Methods transparency** — enough for a serious lab or referee to understand what was done
4. **Reproducibility posture** — seeds, versions, data scope, assumptions, failure modes
5. **No hype science** — no unearned certainty; no marketing language dressed as theorem
6. **Ship bar** — if it would be desk-rejected at those institutions, it does not ship as HYBA science

### Code ↔ documentation elevation (hard rule)

**The code must always be elevated to meet documentation.**

| Principle | Practice |
| --- | --- |
| **Docs do not outrun code externally** | External claims require matching implementation + tests + evidence |
| **Elevate code first** | Prefer raising code/tests/ops to sealed doctrine over diluting the standard |
| **If code lags** | Claim stays **INTERNAL** until elevation complete |
| **Documentation standard** | McKinsey form + sealed claims register + evidence tiers T0–T3 |
| **Engineering standard** | Same bar as docs: falsifiable, measurable, reproducible |
| **Ship bar** | Code and docs must meet each other at the HYBA standard before release |

### Ecosystem containment (hard gate)

**If the bar is not met — if those criteria are not satisfied — it does not leave the ecosystem.**

| Status | Allowed |
| --- | --- |
| Criteria **not** satisfied | Internal only — research, drafts, failed experiments, unvalidated claims |
| Criteria **satisfied** | May leave: customer, press, investor science narrative, product surface, public doc |

**Does not leave until gate passes:** external release, customer handoff, public claim, announcement, investor diligence science, production product science surface.

**No exceptions** for speed, sales pressure, or narrative convenience.

## Business & strategy bar (ubiquitous)

**Approve standard:** Case studies, business plans, strategy, commercial narratives, GTM, pricing logic, and investor business materials — if **HBS, Wharton, MIT Sloan, Deloitte, or EY** would not approve, **HYBA does not ship, announce, or share**.

Same hard gate as science: **fails the bar → does not leave the ecosystem.**

### Required discipline (business)

1. **Logic pyramid** — governing recommendation → drivers → evidence
2. **MECE structure** — no overlapping or missing branches in the argument
3. **Numbers with sources** — every material figure cited or bounded; no orphan metrics
4. **Case integrity** — context, method, result, limits; no cherry-picked anecdotes as proof
5. **Strategy honesty** — alternatives considered, risks, dependencies, what would falsify the plan
6. **Ship bar** — if it would fail a top-MBA case review or Big Four quality review, it stays internal

## Extraordinary claims → extraordinary proof

**Posture:** None of what HYBA has developed is incremental. **Every product is a paradigm shift.** Therefore scrutiny will be greater than for any company before us. We must be prepared for it.

| Rule | Meaning |
| --- | --- |
| **Claim magnitude = proof magnitude** | Larger the claim, heavier the evidence pack |

| **No unearned certainty** | “Paradigm shift” is a burden of proof, not a slogan |
| **Pre-release drill** | If it cannot survive HBS/Wharton/Sloan/Deloitte/EY + Oxford–CERN scrutiny, it does not leave |

## Research, citation & truth posture

**Produce nothing without research and citable evidence.**

| Rule | Practice |
| --- | --- |
| **Cite every material figure** | e.g. DATA TAM, hyperscaler datacentre CAPEX (e.g. $5.3T) — name source, date, scope |
| **No orphan metrics** | If it cannot be cited or bounded, it does not appear externally |
| **Write for posterity** | Assume every sentence will be interrogated, analysed, scrutinised, and shared |
| **Cover in the truth** | Truth is the shield — precise claims, stated limits, full sources |
| **Technology speaks** | Let validated capability carry the argument; proof over puff |
| **Not hyperbole if true** | Strong language is allowed when evidence fully supports it |
| **Confident and proud** | State innovations with institutional confidence — never understate what is validated; never invent what is not |

**Example discipline:** “Hyperscalers will spend $X on datacentre CAPEX over period Y” → cite the primary research/analyst source (and any HYBA derivation method if the number is transformed).
