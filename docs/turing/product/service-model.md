# Enterprise evaluation and service delivery

## Evaluation, not assumed self-service

An organisation should agree a scoped evaluation with an authorised HYBA representative. This documentation does not establish a public signup, deployed customer portal, provisioned runtime, published tariff or accepted service-level commitment.

## Evaluation checklist

| Decision | Evidence or agreement required |
| --- | --- |
| Workload | Problem formulation, admissible domains, representative cases |
| Access | Verified organisation, authorised users, applicable policies |
| Capacity | Definition of the unit, concurrency, limits and containment |
| Data | Classification, location, retention/deletion and export responsibilities |
| Acceptance | Reference results, error handling and reproducibility criteria |
| Commercial terms | Approved pricing, support, term and usage treatment |
| Exit | Access revocation, exports, deletion and unresolved-charge handling |

Logical admission slots in a pilot control implementation must not be described as isolated hardware reservations. Execution records, candidate usage events, billing imports and invoices are separate facts.

## Request an evaluation

Use the established commercial relationship or an independently verified HYBA contact. Include the workload, data classification, desired outputs, integration constraints and acceptance criteria. Do not send secrets or sensitive datasets with an initial enquiry. No new contact address or operational support channel is invented here.
