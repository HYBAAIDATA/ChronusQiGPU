## 1. Findings — severity-ranked
### S1 — CRITICAL / EXPLOITABLE: Live API has no authentication and wildcard CORS
**Status: CONFIRMED. Same as Andre's finding #1.**
**Evidence (traced):**
`hyba_data/api/app.py`, `create_app()`:
```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["*"],
    allow_headers=["*"],
)
```
- No `Depends()`, no header check, no auth middleware on any of the 12 endpoints.
- `SecurityContext.authenticate()` exists in `api/v2/middleware.py` (line 155) — checks `X-API-Key` and `Authorization: Bearer` headers.
- **Nothing mounts it.** `main.py --api-v2` (line 619) just prints: `"V2 API assets: hyba_data/api/v2/endpoints.py, middleware.py, services.py, and SQL schemas"` — it does not run a v2 app.
- `main.py --api` (line 510) runs `uvicorn.run("hyba_data.api.app:app", ...)` — the v1 app with no auth.
- The `zero_trust` module (`ZeroTrustSecurity.authorize()`) and `data_sovereignty` module never touch the live API path.
- The `subscription/middleware.py` `TierMiddleware` exists but is also never wired to the FastAPI app.
**Risk:** If exposed past [localhost](http://localhost), this is an immediately exploitable gap — any origin, any method, no auth.
**Fix required:** Mount `SecurityContext` as FastAPI dependency; restrict CORS to known origins; wire tier middleware.

**Status: NEW FINDING.**

- **BUT** `enterprise/complete_engine.py` (line 485) reports `"encryption_at_rest": "AES-256-GCM"` and `"encryption_in_transit": "TLS 1.3"` — these are string claims, not implementations.

**Risk:** The actual encryption is XOR (trivially breakable). The reporting layer claims AES-256-GCM. A customer or auditor inspecting the report would see "AES-256-GCM" while the code uses XOR.

## 4. Pattern analysis
Three systemic patterns emerge:
1. **Claims layer vs implementation layer gap:** The `enterprise/complete_engine.py` module is a reporting/summary layer that makes strong claims (AES-256-GCM, O(1) search, 15,127x compression, 30+ algorithms, 12 compliance frameworks) that the underlying modules do not implement. The tests validate the claim strings, not the implementations.
2. **Security modules exist but are never wired:** `zero_trust`, `data_sovereignty`, `security/security.py`, `api/v2/middleware.py` — all contain real security logic (RBAC, ABAC, MFA, rate limiting, audit chains, API key management) but none of it is mounted on the live API path. The security code is a library, not a deployed system.
3. **Hardcoded constants presented as measurements:** 92% savings, \$3.56B, 15,127x compression, 30+ algorithms — all are constants in code, not outputs of measurement. Tests assert the constants, creating the appearance of validation.
## 5. Recommended fix priority
1. **S1:** Mount `SecurityContext` as FastAPI dependency on all v1 endpoints; restrict CORS to configurable origins; wire tier middleware. Block deployment until done.
2. **S2:** Remove compliance framework labels from tier definitions and reporting until certifications are obtained. Replace with `"certifications": []` and a comment: `# Add when certified`.
3. **S5:** Replace XOR with `cryptography.hazmat.primitives.ciphers.aead.AESGCM` or integrate with cloud KMS. Update the reporting layer to reflect actual algorithm.
4. **S3:** Move ROI constants to a `benchmarks/` config file; label as projections, not results. Remove from UAT_[RESULTS.md](http://RESULTS.md).
5. **S4:** Add `random.seed(42)` or `np.random.seed(42)` at module load in `solvers.py`, `manifolds.py`, `operators.py`. Add a `--seed` CLI argument.
6. **S6:** Change `"O(1)"` to `"O(steps × faces)"` in reporting; or implement actual O(1) lookup with a hash table.
7. **S9:** Wire actual MFA verification in `/auth/mfa/verify`; use HMAC-SHA1 per RFC 6238.
8. **S7/S8:** Replace `30` with actual count from `len(OPERATOR_FACTORIES) + len(ORACLE_FACTORIES)`; replace `15127.0` with measured compression ratio.
