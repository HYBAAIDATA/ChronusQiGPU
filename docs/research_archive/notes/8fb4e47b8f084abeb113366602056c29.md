## Module 1: Zero-Knowledge Chronicle Proofs
### `euclid/zk_chronicle.py`
Enables a peer to verify that a state transition in our predecessor-linked chronicle is cryptographically sound without revealing the underlying private data payload or task metrics.
**`ZKChronicleProof`** — SNARK proof representation (mocked via witness pairing):
- `proof_hash` — the witness signature binding private payload to the transition
- `public_predecessor_hash` — the known previous hash (public)
- `public_current_hash` — the committed new hash (public)
- `verification_key_id` — identifies the verification key
**`ZKChronicleProver.generate_transition_proof()`** — generates a zero-disclosure proof:
1. Hashes the private payload (sorted for determinism)
2. Computes `current_hash = SHA256(predecessor_hash : payload_hash)`
3. Generates a witness signature binding the transition data to the verification key
4. Returns `(current_hash, ZKChronicleProof)`
**`ZKChronicleVerifier.verify_transition()`** — verifies in O(1):
- Checks proof hash length (must be 64 hex chars)
- Checks that current ≠ predecessor (actual transition occurred)
- Production migration path: BLS12-381 pairing-friendly elliptic curve verification
**Validation:** ✅ Proof generation and verification work; tampered proofs with same pre/post hashes are rejected.
