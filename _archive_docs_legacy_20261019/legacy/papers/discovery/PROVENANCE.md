## Pearl's Causal Ladder & Do-Calculus status

The user specifically asked about "pearl ladder and du calculus" (Judea Pearl's causal ladder and do-calculus).

**What exists in the HYBA archive:**

1. **`FINANCIAL_INTELLIGENCE_SUBSTRATE_ARCHITECTURE.md`** (Section A3) describes a `CausalInferenceEngine` design that explicitly references:
   - Do-calculus for causal effect estimation
   - Structural causal models (SCMs)
   - Counterfactual simulation
   - Causal graph topology analysis
   - PC/FCI causal discovery algorithms

   However, this is a **design-phase document** — the implementation is shown as a stub (`pass`).

2. **`intelligence_lobes.py`** has `CausalIntelligence` (Layer 4) and `CounterfactualIntelligence` (Layer 5), but:
   - `CausalIntelligence` does hub isolation (DAG construction for mining lanes), not Pearl's do-calculus
   - `CounterfactualIntelligence` does constructor-theory transform validation, not Pearl's counterfactuals
   - Both are mining-focused, not general-purpose causal inference

3. **`bitcoin_phi_pci.py`** has `BlockchainCausalAnalyzer` with time-lagged causal chains, but the `compute_causal_chains` method raises `ContractViolationError` — it refuses to use floating-point correlation and demands exact rational substrate.

4. **`causal_triage.py`** does exact spectral root matching for clinical pathology — a specialized causal detection, not general do-calculus.

**What does NOT exist in the HYBA archive:**

- A general-purpose Pearl do-calculus implementation (do-operator, backdoor criterion, frontdoor criterion, identifiability)
- A Pearl causal ladder (association → intervention → counterfactual) implementation
- A general SCM (Structural Causal Model) framework with exogenous variables, structural equations, and intervention operators
- A counterfactual simulation engine (computing P(Y | do(X), y_observed))

**What the EUCLID-CORE `toe_bridge.py` already has:**

The current `toe_bridge.py` has a quantum-measurement-based causal analysis (`explain_causality`) that ranks factors by quantum expectation values. This is NOT Pearl's do-calculus — it's quantum measurement theory. The bridge would need a new capability to implement Pearl's causal ladder.

## Recommendation

To elevate the EUCLID-CORE predictive-causal intelligence with Pearl's causal ladder and do-calculus, the path is:

1. Use the `FINANCIAL_INTELLIGENCE_SUBSTRATE_ARCHITECTURE.md` design as the specification.
2. Implement a `CausalLadder` capability in the Intelligence layer with three rungs:
   - **Rung 1 (Association):** P(Y | X) — already covered by `state_tomography` (Born probabilities)
   - **Rung 2 (Intervention):** P(Y | do(X)) — needs do-operator implementation
   - **Rung 3 (Counterfactual):** P(Y_x | X=x', Y=y') — needs structural equation model

4. Use the `outcome_verification.py` evidence framework to classify causal claims as PROVEN/MEASURED/SUPPORTED/HYPOTHESIS.
