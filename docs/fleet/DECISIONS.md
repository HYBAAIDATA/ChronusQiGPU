# Chronus iGPU fleet: decisions on the Planetary Fabric spec (Rev. 3)

Copyright (c) 2026 HYBA Software Ltd. All rights reserved. Chronus is a HYBA Data product.

Decided on 11 November 2026 under delegated authority from Andre Taylor-Morris (Founder and CEO). Each decision below resolves a placeholder of the PULVINI / Chronus Planetary Fabric four-phase spec (Rev. 3) that the fleet code (`src/chronus/fleet/`) touches, or a gap the spec leaves implicit. Placeholders the fleet does not touch are listed at the end and remain open.

## Placeholders resolved

| Item | Decision | Where it is enforced |
|---|---|---|
| **P2** `MAX_H4_DIAMETER` | **5**, computed, not typed in. Breadth-first search over the exact 600-cell graph built by the existing `chronus.ns_dec.build_h4_600_cell_polytope` (120 vertices, 720 edges, every vertex of degree 12) finds eccentricity 5 at every vertex. The same graph yields 1,200 triangular faces and 600 tetrahedral cells as 3- and 4-cliques. The Coxeter group order of 14,400 is quoted from the spec and not recomputed. | `crossbar.max_h4_diameter`, `H4Crossbar.route` (any route longer than the diameter is refused) |
| **P2a** `CONSTRUCT_RECOVERY_PATH` | **Candidate (i), a circuit.** The recovery path is a deterministic re-execution plan: each orphaned lease group is assigned to a surviving node by largest-remainder apportionment over measured throughput. It is built from the faulted state and the survivors' weights only. A fleet fault leaves a set of unfinished tiles whose inputs are immutable, so re-execution restores the exact state; a geodesic (ii) or defect-surface walk (iii) is not needed. | `recovery.RecoveryChannel.construct_recovery_path` |
| **P2b** action functional | **Deleted**, as the spec directs for candidate (i): a circuit has no action functional. | — |
| **P2c** blind check | Implemented as specified. Channel A (recovery) never holds a reference to channel B or to V. It commits to the recovered outputs with a Merkle root, and only then does channel B draw V with a CSPRNG (default: half the recovered tiles, never fewer than one), recompute V on the pure-Python reference and return pass or fail with counts. A failure quarantines the nodes that produced wrong tiles and opens one further round on other nodes; a second failure fails the job closed. **ONE_CYCLE = one recovery round**; every receipt carries `one_cycle` for each incident. | `recovery.BaselineChannel`, `coordinator._close_incident` / `_blind_check` |
| **P3** pool ratios | **PREFILL_RATIO = 1/4, DECODE_RATIO = 3/4** (sum 1; any sum above 1 is refused). A pool is a budget of tiles in flight: floor(tier lanes × ratio), so 8,192 and 24,576 at Tier 1; the budgets follow the tier when the fleet scales. Each work unit names its pool (default `decode`). The spec's `kv_cache_passthrough` handoff is not part of the fleet: it holds no KV cache, and callers chain jobs by passing one job's verified output to the next. | `scheduler.pool_budgets`, `LeaseScheduler._fits_pool` |
| **P6** FIPS 204 library | **pyca/cryptography ≥ 47 (OpenSSL backend)**, reached through the existing `MLDSASigner` in `chronus/chronus_gpiu-v36.py` (merged in PR #28), with ML-DSA-65. This matches the `cryptography>=47.0` floor already in `pyproject.toml`. It is a standard implementation of FIPS 204; it is not a claim of a FIPS 140-3 validated module. One key per fleet: a 32-byte FIPS 204 seed in the coordinator state directory, mode 600, with no KMS or HSM custody. | `signing.load_mldsa_signer`, `signing.FleetSigner` |
| **P7** "Hermiten" | **Not "Hermitian".** "Hermiten" is HYBA's commercial term: on owner direction (11 November 2026), HYBA bills 25% of verified avoided spend, and HYBA receives that 25%. It is a different quantity from the 25% in spec 4.1 / P11, which is an equal four-way split among designated participants. The fleet does not bill. It records verified, measured contribution that a billing system may use. | `receipts` (per-device contribution) |
| **P7a** value-share matrix | **V[i][j] = work items that participant i's devices executed, and that were accepted after verification, for jobs submitted by participant j in the closed period.** Participants are owners: the `--owner` a worker joins with and the submitter of a job. Entries are counts taken from signed receipts. | `value_share.build_value_share_matrix`, `contributions_from_receipts` |
| **P7b** definition | **Choice (a), as the spec states:** the right Perron eigenvector (V s = ρ s), normalised to sum 1, computed in float64 and compared with an absolute tolerance of 1e-9. | `value_share.perron_vector` |
| **P10** AL HARAS ledger | **Schema `chronus.fleet.al-haras-anchor/v1`:** JSON Lines with `schema, seq, prev_hash, recorded_at, kind, digest, meta, entry_hash`. `entry_hash` is the SHA-256 of the canonical entry without itself, and `prev_hash` chains entries from 64 zeros. **Append protocol:** one writer; the whole chain is verified on open; each append holds an exclusive file lock, writes one line, then flushes and fsyncs. **Verification:** recompute every hash and link from line 1 and report the first bad entry. Anchored kinds are coordinator start and joins (`note`, with each machine's backend selection), tier changes and grants (`tier`), scale events (`scale`), fabric snapshots, incidents and receipts (with the backend record). The ledger is tamper-evident and local; it is not replicated and is not called immutable. | `ledger.AnchorLedger`, `ledger.verify_ledger` |
| **P11** designated set | **Exactly four, each at 0.25, all others at 0**, enforced as written. The Perron vector of an irreducible V is strictly positive, so V can only contain the four designated participants, and their shares are equal only when their contributions are balanced. As written, P11 is therefore a balance check, not an allocation rule. See "Open for Andre" below. Reconciliation runs in Tier 4 and the Scale tier. | `value_share.reconcile_value_share` |

## Gaps the spec leaves implicit, decided

| Gap | Decision |
|---|---|
| `PHASE_n.connectors` (used by PHASE_GATE, never defined) | The transports a tier needs: Tier 1 `{fleet-http}`, Tiers 2–4 and Scale `{fleet-http, fleet-tls}`, so TLS is mandatory from Tier 2. The onboarding connector list of spec 1.1 (S3, Azure Blob and so on) remains with `chronus.service.instant_provisioning` and `chronus.storage.connectors`, which the fleet does not change. |
| Warps and lanes for a software iGPU | One virtual unit is one logical lane, and 32 lanes form one logical warp. A device joining at 80, 800 or 8,000 virtual units occupies 3, 25 or 250 logical warps. The fleet's composed lattice is the sum over admitted devices, and demand is checked against the tier's entitlement on every join, every job and every fabric tick (`TIER_GATE`, the spec's `PHASE_GATE`). These are scheduling units, never physical cores. |
| Resident rungs | Exactly {80, 800, 8,000}. The repository's `ResidentConfig` accepts 1 to 65,536; the fleet restricts it to the manifesto's three rungs. |
| Storage units | 1 TB = 10^12 bytes. Storage used = bytes the coordinator holds (job inputs and outputs in memory, receipts on disk, the ledger). |
| `phase_complete` / `advance_phase` | Superseded by **tiers with the option to scale** (next table). A tier changes only through the owner's signed grant or selection, or when a grant expires; every change is anchored in the ledger. |
| `run_fabric` cadence | One tick every 2 s: apply new grant and selection files, retire expired grants, admit waiting machines and queued jobs a grant now covers, check demand against the entitlement (newest machines wait if it is over), then hash the state snapshot (timestamps excluded) and anchor the SHA-256. An identical snapshot is not re-anchored. |
| 600-cell placement and use | Each node is placed on a vertex by hash with linear probing. The crossbar orders work stealing (nearest victim first). The spec's 130 Tb/s figure and stall assertions concern a hardware interconnect: the fleet runs over HTTP and makes no bandwidth claim. |
| Same-hash verification policy | 1 tile in 8 (125,000 ppm), chosen by HMAC under a coordinator-only secret. At least one tile per device per job is always checked. On disagreement, the reference arbitrates and every other tile of that device in the job is checked. One wrong answer quarantines the device. |
| Operational defaults | Port 8740. Bind to loopback unless `--host` is given. Heartbeat 1 s; node declared lost after 5 s; lease TTL 15 s renewed by heartbeats, with a hard maximum of 10 min; 4 attempts per tile group; request body up to 64 MiB; clock skew up to 5 min; tokens of at least 32 characters (256-bit by default). TLS uses a self-signed ECDSA P-256 certificate valid for 825 days. |
| Metal engines | MLX first (Apple Silicon, GPU stream only; refused if `mx.metal.is_available()` is false), then PyObjC Metal with a compiled MSL kernel. Both must reproduce every known answer before they receive work. |

## Owner decisions, 11 November 2026

| Decision | What it means in the code | Where it is enforced |
|---|---|---|
| **Tiers with option to scale, per Andre 11 Nov 18:23** ("we need to find a way to tier with the option to scale") | The four spec phases are commercial tiers, and their figures are the tier's provisioned entitlement: 1,024 / 10,000 / 40,000 / 160,000 logical warps × 32 lanes and 100 / 1,000 / 10,000 / 100,000 TB. Above Tier 4 sits the Scale tier, set per contract by an explicit operator figure (at least Tier 4's; never open-ended). Demand beyond the entitlement records a scale event (demand, entitlement, next tier, timestamp), is admitted under a valid scale grant (ML-DSA-65, signed by the coordinator owner's key, naming the tier or figure and an expiry) and is otherwise queued with "scale available: Tier N+1": a fifth Mac joins and waits instead of being turned away. Downgrade is always possible (`tier set`), and an expired grant moves the fleet down. Entitlements are provisioning, never performance claims. | `phase` (tiers, `scale_tier`, `TIER_GATE`), `scale` (grants, selections, events), `coordinator._admit`, `install_grant`, `select_tier`, `chronus-fleet tier status\|grant\|set` |
| **Backend-agnostic selection, per Andre 11 Nov 18:33** ("it could be that ours is selected over the host") | Every run detects the backends, then selects from `--backend auto\|igpu\|metal\|opencl\|cuda\|simd\|reference` and `--prefer ours\|host` (default `ours`). `ours` selects the Chronus iGPU (Mode A, the resident lattice: HYBA's software-defined GPU, a first-class GPU route) even when the host has a GPU; `host` selects Metal, CUDA or OpenCL when present and self-tested. A named backend runs exactly there or fails closed. The old order that put the host GPU first is gone; measured throughput no longer reorders the choice. `requested_backend`, `detected_backends`, `preference`, `executed_backend` and `fallback_reason` are in every tile record, receipt and receipt anchor. The `silicon` field still states the physical silicon under a route (the Chronus iGPU runs on the host's general-purpose cores); route labels never call the Chronus iGPU "CPU" or a fallback. CUDA is a probe of `cupy` or `numba.cuda` that fails closed (no CUDA kernels yet). | `backends`, `adapters.IGPUAdapter`, `AdapterRegistry.select`, `cuda`, `worker`, `coordinator._check_record` |

## Not touched by the fleet (left open)

- **P1b** denominator growth policy (Binet–Zeckendorf ingest).
- **P4** `STALK_KIND` and `norm_metric` (sheaf prompt filtration).
- **P5** `ANYON_MODEL` (Z5 parafermion versus SU(2)_4 = Z[ζ12]).
- **P8** `to_base_phi()` uniqueness domain.
- **P9** quotient structure and STARK parameter set.
- **P12** `store_folded` wiring (OVID + phyllotaxis + Theseus).
- Spec 1.1 (instant zero-copy onboarding with customer-managed keys), 1.2 (in-place schema discovery) and 3.1 (air-gapped deployment) are outside the fleet. The fleet makes no outbound connection except to the coordinator URL it is given, so it can run on an isolated network.

## Open for Andre

1. **P11 as written cannot allocate.** If the intent is that each of four designated participants receives a quarter, that is a fixed split and needs no Perron vector. If the intent is shares proportional to verified contribution, the four-way equality assertion has to go. The fleet enforces the spec as written until one of these is chosen.
2. **Who the four designated participants are** (for example the four HYBA companies) is not stated in the spec. The fleet takes them as an argument.
