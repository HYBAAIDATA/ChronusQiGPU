## Thesis

PYTHIA mining is a Bitcoin mining intelligence and execution system. PYTHIA does not change Bitcoin consensus. It composes intelligence, memory, mathematical search structure, Turing quantum/VQC capabilities, Kellogg tensor mathematics and Chronus execution to decide how an already-authorised nonce lease is searched. Every candidate is still judged by exact SHA256d, the negotiated target, current Stratum work identity and stale/epoch rules. Pool acceptance exists only when the pool literally acknowledges the submission.

The search has structure, and PYTHIA uses that structure to search. Hendrix is
the default production search algorithm. PYTHIA composes supposition and its
available Turing support arsenal — including tunnelling, annealing, swarming
and entanglement — around that search. The 32-face, 11D, H4/600 and Turing
Hilbert structures support the complete itinerary Hendrix traverses; they do
not replace Hendrix as the search identity.

The production objective is to improve useful search/execution efficiency while preserving complete truth and evidence boundaries. The engineering target of 10 EH/s aggregate remains a capacity target until measured on the actual fleet.

## PYTHIA

## Supposition

A proposed search ordering is a supposition until real hashing evaluates it. The exact historical `SuppositionEngine.form_supposition` source has not been recovered from current Git history or the recovered donor archives. The production implementation therefore records an explicit hypothesis receipt without falsely claiming the original class has been restored.

## Turing and quantum/search capability

Hendrix is PYTHIA's default production search algorithm. PYTHIA may compose
the repository's available Turing/quantum capabilities in support of that
search, including tunnelling, annealing, swarming, entanglement/state
operations, exact and Grover-style search, quantum walks including
Szegedy-family surfaces, collapse/measurement, VQE, QAOA, QFT, simulation and
the recovered 32-face VQC lineage. Supporting capability need not execute on
every job, but it must remain reachable and may not silently replace Hendrix
as the default search identity.

A trained historical VQC checkpoint can contribute candidate ordering only. It cannot prune an authorised lease, establish a valid share or create a pool outcome.

## Kellogg

Kellogg is the tensor plane. Tensor computation is available to PYTHIA/Turing/Chronus where useful, but Kellogg does not own mining intelligence, quantum authority or execution routing.

## Chronus

Chronus is the heterogeneous execution architecture and is not defined by CUDA, NVIDIA, OpenCL or Metal. Vendor/runtime interfaces are adapters where present. The canonical joined execution route can promote the H4/600-cell fabric into 600 logical work shards over a nonce lease while physical fleet size scales independently beneath that logical topology.

Hashrate is measured completed SHA256d work divided by measured elapsed time. Mathematical topology and configured worker count never substitute for measured H/s.

## Historical Bitcoin memory

PYTHIA can ingest Bitcoin Core's active chain from genesis to tip. The corpus always preserves independently validated 80-byte headers and exact Binet/Fibonacci/Zeckendorf/Cassini/Lucas indices. Optional full-block custody preserves the exact serialized block bytes, including transactions, returned by Bitcoin Core and anchors them to the validated header.

Historical valid nonces may train the recovered Turing VQC as supervised examples. They are not evidence that future winning nonces are predictable.

## Salamander

Salamander owns bounded self-healing and optimisation. It observes canonical mining evidence, diagnoses degradation/failure, authorises only bounded actions, acts through the existing recovery/optimisation authorities, measures the result, retains or rolls back changes and appends durable hash-chained evidence. It does not plan nonce search or determine share validity.

## Truth boundary

Production claims require evidence. The system must not fabricate pool state, hashrate, device state, jobs, candidates, shares, accepted outcomes, quantum hardware, fleet fan-out or performance. Unavailable evidence stays unavailable.

Source integration, passing software tests, live-pool evidence, physical-fleet evidence, accepted-share evidence and performance evidence are separate proof levels and must remain labelled separately.
