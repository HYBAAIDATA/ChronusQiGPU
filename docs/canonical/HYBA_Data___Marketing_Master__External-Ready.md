## 4. Problem / number / mechanism / ask (McKinsey one-pager)

### Problem

AI and data infrastructure are increasingly **memory-bound**. Organisations buy more DRAM and GPUs to move and hold working sets, while power, footprint, and cost constrain growth. Traditional software charges seats and maintenance; it does not take responsibility for measured infrastructure savings.

### Number (use only with citation or label illustrative)

- Qualitative EXTERNAL: memory is a material bottleneck for AI/infra workloads.
- Any $T CAPEX/TAM figure: **cite source, date, scope** or keep INTERNAL per claims register.
- Customer math: use sensitivity `savings ≈ spend × f × (1 − 1/m)` with f = eligible fraction, m = sealed/illustrative multiplier (1.5× / 2.0× / 2.6× until production m_eff).
- **φ-power law (always):** `capacity(d)=φ^d`, `reduction(d)=1−φ^{−d}`. Folding and compression are one system — change power `d` to move the ratio. M1 = **d=2** (~2.62×); M2 = **d=4** (~6.85× / ~85.41% W-reduction). Ref: [φ-Power Fold Law — Investigation, Test & Fix (19 July 2026)](%CF%86-Power%20Fold%20Law%20%E2%80%94%20Investigation,%20Test%20&%20Fix%20(19%20J%2036b8e3d5002d427791863e417addf262.md)

### Mechanism

1. **PULVINI** — φ-fold memory on **structured numerical / φ-pattern** working sets at named power `d`  
2. **HERMES** — GPU / compute scaling on the acceleration path (separate product)  
3. **Stack (optional)** — fold memory *and* scale GPUs in one engagement when both pains exist  
4. **Salamander** — implemented self-heal / self-optimise controls  
5. **Scrutiny / claim gates** — separate code evidence from operational/economic claims  
6. **Commercial** — 25% of measured savings; $0 maintenance line  

### Ask

90-day measured pilot on one memory-bound workload: baseline → deploy → measure → gain-share term sheet.
