## Case 1 — Hyperscaler memory wall (commercial)

### Problem

AI inference/cache fleets are memory-bound. Buying more DRAM/GPU is the default; software that **truncates** state destroys quality.

### Mechanism

| Layer | Role |
| --- | --- |
| Fold | PULVINI φ-fold on **structured** working sets — reconstruct by unfold |
| Quantum-for-data | QATL / honest quantum elevate tensors; search/cost models without QPU |
| Commercial | 25% of **measured** savings; no maintenance; no onsite eng army |

### Why not truncate

Truncation is irreversible loss. Fold keeps a reconstructable state (recon-error gate). That is the product difference.

### Illustrative economics

Use sensitivity only: `savings ≈ S_memory × f × (1 − 1/m)` with m ∈ {1.5, 2.0, 2.6} until full kernel seal.  

**Repo:** `python_backend/hyba_data/savings_metering.py` · pilot: [HYBA Data — Pilot Measurement Protocol](HYBA%20Data%20%E2%80%94%20Pilot%20Measurement%20Protocol%209c56caf52be040a28f37da830164758e.md)

### Ask

## Case 4 — Quantum-for-Data security posture (why quantum stays)

### Problem

Long-term secrecy of archives is under pressure (harvest-now decrypt-later). Businesses need a path that is honest about PQC-era risk without false “quantum hard drive” claims.

### Mechanism

| Classical truth we keep | HYBA Data quantum-for-data role |
| --- | --- |
| Raw bytes stay on classical storage | Fold sensitive **working sets** intelligently |
| PQC migration is industry-wide | Number-theoretic / integrity posture on folded state |
| QKD is niche | We do not overclaim QKD; we claim maths-first elevation |

### Articulation (locked)

**Quantum serves data** — keys, patterns, elevated tensors, search cost models — not mining hashrate.

### Ask

Security architecture workshop: what is folded vs stored raw; claim register gates on external language.
